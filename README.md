# vshell

Эмулятор командной оболочки UNIX-подобной ОС, написанный на Go.

Текущее состояние: **Этап 5 — Дополнительные команды**. Эмулятор загружает виртуальную
файловую систему из ZIP-архива (обычного или закодированного в base64) и работает с ней только
в памяти. `ls` и `cd` работают с VFS так же, как GNU `ls` и встроенная `cd` bash; `mv`
переименовывает и перемещает файлы и директории, меняя VFS строго в памяти; `uname` выводит
данные реальной хостовой ОС, `clear` очищает экран. Параметры командной строки задают путь к
VFS и к стартовому скрипту; при запуске они выводятся для отладки.

## Требования

* Go 1.22 или новее
* для пересоздания архивов VFS: `zip`, `base64`, `fold`

## Использование

```
./run.sh [-vfs path] [-script path]   # сборка и запуск
make build                            # сборка bin/vshell
make test                             # запуск тестов
make check                            # gofmt + go vet
make demo                             # запуск тестовых скриптов хоста из scripts/
```

`run.sh` запускает эмулятор из той директории, где находится пользователь, поэтому
относительные пути в параметрах отсчитываются от текущей директории.

## Параметры командной строки

| Параметр | Назначение |
| ----- | ----- |
| `-vfs path` | путь к ZIP-архиву VFS (обычному или в base64); без него VFS пуста |
| `-script path` | путь к стартовому скрипту, выполняемому перед интерактивным сеансом |
| `-h`, `-help` | справка по параметрам |

Допустимы формы `-vfs path`, `-vfs=path`, `--vfs path` и `--vfs=path`, параметры можно
указывать в любом порядке. Позиционные аргументы не принимаются.

### Отладочный вывод

При каждом запуске эмулятор выводит в поток ошибок все параметры и их значения.
Значения выводятся в кавычках, чтобы были видны пробелы; незаданные параметры помечаются.

```
$ ./run.sh -vfs vfs/minimal.b64
[debug] vfs: "vfs/minimal.b64"
[debug] script: (not set)
user@host:/$
```

## Виртуальная файловая система

* Источник VFS — ZIP-архив. Двоичные данные хранятся в base64: в репозитории лежат только
  текстовые файлы `vfs/*.b64`, а эмулятор принимает как base64-текст (с переносами строк
  или без), так и обычный `.zip` — формат определяется по сигнатуре ZIP.
* Архив читается с диска только один раз и целиком разбирается в дерево в памяти.
  Ничего не распаковывается на диск и не изменяется; все дальнейшие операции, в том числе
  изменения VFS командой `mv`, идут только в памяти и пропадают при выходе. Скрипт
  `scripts/test_mv.sh` проверяет по контрольной сумме, что файлы VFS на диске не меняются.
* Записи сохраняют права доступа и время изменения из архива. Время в формате MS-DOS
  (без часового пояса) считается местным, как в `unzip`. Директории, которых нет в архиве
  явно, но которые следуют из путей файлов, создаются с правами `drwxr-xr-x` и временем
  записи, из-за которой они появились. Пустые директории сохраняются. Содержимое файлов
  (в том числе двоичное) хранится в памяти, суммарно не более 64 МиБ.
* Домашняя директория пользователя в VFS — `/home/<имя пользователя хоста>` (для
  суперпользователя `/root`). Как при входе в систему, сеанс начинается в ней, если она есть
  в VFS, иначе в корне `/`.
* Пути разбираются по элементам, как в ядре UNIX: `.` и `..` поддерживаются, `..` в корне
  остается в корне, а путь через файл (`file/x`, `file/`, `file/..`) дает `not a directory`.
* Если VFS не загружается, эмулятор сообщает об ошибке с путем к файлу и завершается со
  статусом 1, не запуская стартовый скрипт.

### Варианты VFS

| Файл | Содержимое |
| ----- | ----- |
| `vfs/minimal.b64` | один файл `readme.txt` в корне |
| `vfs/multi.b64` | семь файлов с разными правами, в том числе двоичные `logo.png` и `data.bin`, и директория `docs` |
| `vfs/deep.b64` | 13 директорий с вложенностью до пяти уровней (`/home/guest/projects/vshell/src/main.go`), пустая `/tmp`, скрытые `.profile` и `.cache`, имя с пробелом `my documents`, 25 файлов в `/usr/bin` и старые даты в `/etc` и `/var` |

```
$ ./run.sh -vfs vfs/deep.b64
user@host:/$ tree /home
/home
└── guest
    ├── my documents
    │   └── report.txt
    ├── notes.txt
    └── projects
        └── vshell
            ├── README.md
            └── src
                └── main.go

```

Новый вариант VFS делается из любой директории утилитой `scripts/mkvfs.sh`: она упаковывает
директорию в ZIP в конвейере и сразу кодирует его в base64, так что двоичный архив на диск
не попадает. Права и время изменения файлов сохраняются.

```
scripts/mkvfs.sh path/to/dir vfs/my.b64
```

## Стартовый скрипт

Стартовый скрипт — текстовый файл с командами эмулятора, по одной на строку.

* Каждая строка выводится после промпта, а затем выполняется, так что на экране видны и ввод,
  и вывод — как в диалоге с пользователем. Пустые строки и комментарии тоже выводятся.
* Комментарии используют синтаксис Go: `//` начинает комментарий до конца строки. Как и `#`
  в UNIX-оболочке, `//` открывает комментарий только в начале слова, поэтому `a//b`,
  `"// x"`, `'//x'` и `\//x` остаются обычными аргументами. Комментарии работают и в
  интерактивном режиме.
* Каждая ошибка сообщается с именем скрипта и номером строки, после чего скрипт продолжается
  со следующей строки, как в неинтерактивном bash.
* `exit` в скрипте завершает и скрипт, и весь сеанс с указанным статусом.
* Если скрипт завершился без `exit`, начинается интерактивный сеанс в той директории, где
  остановился скрипт; статус последней команды скрипта сохраняется.
* Строки с окончаниями CRLF обрабатываются корректно.

```
// Пример стартового скрипта
cd /etc           // комментарий в конце строки
ls /nope
```

```
user@host:/$ // Пример стартового скрипта
user@host:/$ cd /etc           // комментарий в конце строки
user@host:/etc$ ls /nope
vshell: init.vsh: line 3: ls: cannot access '/nope': no such file or directory
user@host:/etc$
```

## Возможности

### Prompt

Промпт формируется на основе реальных данных хостовой машины: имени пользователя и имени хоста
(без доменной части), за которыми следует текущая директория VFS. Домашняя директория и пути
внутри нее начинаются с `~`; суперпользователь получает `#` вместо `$`.

```
username@hostname:~/docs$
```

### Парсер

Правила экранирования и кавычек соответствуют стандарту POSIX shell.

| Ввод | Аргументы | Правило |
| ----- | ----- | ----- |
| `ls a   b` | `a`, `b` | пробелы разделяют аргументы |
| `ls "my dir"` | `my dir` | двойные кавычки сохраняют пробелы |
| `ls 'my dir'` | `my dir` | одинарные кавычки сохраняют всё буквально |
| `ls my\ dir` | `my dir` | обратный слеш экранирует следующий символ |
| `ls "a \"b\""` | `a "b"` | внутри двойных кавычек `\` экранирует `"`, `\`, `$`, `` ` `` |
| `ls a"b c"d` | `ab cd` | соседние части объединяются в один аргумент |
| `ls ""` | (пустая строка) | пустые кавычки дают пустой аргумент |
| `ls a // b` | `a` | `//` в начале слова начинает комментарий |
| `ls a//b` | `a//b` | `//` внутри слова — обычные символы |
| `cd ~/docs` | `/home/user/docs` | `~` в начале слова, перед `/` или отдельно, заменяется домашней директорией |
| `ls "~" ~bob a~` | `~`, `~bob`, `a~` | `~` в кавычках, `~user` и `~` внутри слова не раскрываются |

### Команды

| Команда | Поведение |
| ----- | ----- |
| `ls [-al] [path...]` | как GNU `ls`: содержимое директорий и имена файлов, по умолчанию текущая директория |
| `cd [dir \| -]` | как `cd` в bash: смена текущей директории VFS |
| `mv [-fnv] src dest`, `mv [-fnv] src... dir` | как GNU `mv`: переименование и перемещение в памяти |
| `uname [-asnrvm]` | данные реальной хостовой ОС |
| `clear [-x]` | очистка экрана терминала |
| `tree [path]` | утилита: дерево директории, как UNIX `tree` |
| `exit [n]` | завершает сессию со статусом `n` (mod 256) или статусом последней команды |

Конец ввода (Ctrl-D) также завершает сессию.

Опции команд разбираются как в `getopt`: буквы можно объединять (`-la`), опции можно ставить
между операндами (`ls docs -l`), `--` завершает опции, одиночный `-` — операнд.

#### ls

* Без операндов выводит текущую директорию. Сначала выводятся операнды-файлы, затем
  содержимое директорий; и те, и другие отсортированы по имени побайтно (как в локали C).
  Если операндов несколько, перед содержимым каждой директории печатается заголовок `dir:`,
  а группы разделяются пустой строкой.
* Имена раскладываются по колонкам сверху вниз, как в терминале шириной 80 символов:
  выбирается наименьшее число строк, при котором колонки с промежутком в два пробела
  помещаются в ширину.
* `-a` показывает скрытые записи (имя начинается с точки) и `.` и `..` в начале списка.
* `-l` — длинный формат: права, число ссылок, владелец и группа (пользователь и его основная
  группа на хосте), размер, время изменения и имя. Время показывается с часами и минутами,
  если ему меньше полугода, иначе с годом. Над содержимым директории выводится `total` —
  занятое место в КиБ при блоках по 4 КиБ; размер директории — 4096 байт, как в ext4;
  число ссылок директории — 2 плюс число поддиректорий.
* Недоступные операнды сообщаются по одному (`cannot access`), остальные все равно выводятся,
  статус 2. Неизвестная опция — тоже статус 2.

#### cd

* `cd dir` — относительно текущей директории или от корня, если путь начинается с `/`.
* `cd` без аргумента и `cd ~` переходят в домашнюю директорию; если ее нет в VFS, это
  ошибка, как в bash при несуществующем `$HOME`.
* `cd -` возвращается в предыдущую директорию и печатает ее путь.
* Отсутствующий путь, файл, больше одного аргумента или опция (`cd -P`) — ошибка; текущая
  директория не меняется.

#### mv

* `mv src dest` переименовывает `src` в `dest`; если `dest` — существующая директория,
  `src` перемещается в нее под своим именем. `mv src... dir` перемещает несколько источников
  в директорию. Директории перемещаются вместе со всем содержимым.
* Как в `rename(2)`, существующий файл заменяется файлом, а пустая директория — директорией.
  Каталоги, из которых и в которые перемещена запись, получают текущее время изменения.
* `-n` не заменяет существующие записи (такой источник молча пропускается), `-f` отменяет
  предшествующий `-n`, `-v` печатает каждое перемещение: `renamed 'a' -> 'b'`.
* Если перемещается директория, в которой находится текущая (или одна из ее родительских),
  промпт показывает новый путь.
* Ошибки сообщаются по каждому источнику в формате GNU `mv`, остальные источники все равно
  перемещаются; любая ошибка дает статус 1. Нельзя переместить корень, `.` и `..`,
  директорию в саму себя или ниже, файл сам на себя, файл на место директории и наоборот,
  директорию на место непустой директории; при нескольких источниках цель должна быть
  существующей директорией.

#### uname

Выводит данные хостовой ОС: `-s` имя ядра, `-n` сетевое имя узла, `-r` выпуск ядра,
`-v` версию ядра, `-m` тип машины, `-a` все сразу. Значения всегда идут в этом порядке
независимо от порядка опций; без опций выводится имя ядра. На macOS и BSD данные берутся из
`sysctl`, на Linux из `/proc/sys/kernel`; на других системах — из среды выполнения Go,
а недоступные значения заменяются на `unknown`.

```
user@host:/$ uname -a
Darwin host.local 25.5.0 Darwin Kernel Version 25.5.0: ...; root:xnu-.../RELEASE_ARM64_T8132 arm64
```

#### clear

Выводит управляющие последовательности ANSI: курсор в начало, очистка экрана и очистка
буфера прокрутки (`ESC[H ESC[2J ESC[3J`), как `clear` из ncurses. С `-x` буфер прокрутки
сохраняется.

#### tree

Выводит `path` (по умолчанию текущую директорию) и все, что под ним, деревом с сортировкой по
имени и итогом `N directories, M files`, как UNIX `tree`. Скрытые записи пропускаются, как в
`tree` без `-a`. Это вспомогательная команда этапа 3, когда `ls` и `cd` еще были заглушками.

## Тестовые скрипты хоста

Скрипты в `scripts/` собирают эмулятор, запускают его с разными параметрами из корня
репозитория и печатают командную строку каждого запуска и его статус выхода.
Интерактивный ввод в них не подается (или подается через конвейер), поэтому сеанс
завершается сам. Временные файлы создаются в `bin/` и удаляются по завершении скрипта.

| Скрипт | Что проверяет |
| ----- | ----- |
| `scripts/test_options.sh` | без параметров, только `-vfs`, только `-script`, оба в разном порядке, формы `--name=value`, пути с пробелами и абсолютные пути, `-h` |
| `scripts/test_startup.sh` | комментарии и кавычки в скрипте, ошибки с номерами строк, `exit` в скрипте, интерактивный сеанс после скрипта |
| `scripts/test_errors.sh` | неизвестный параметр, параметр без значения, лишний аргумент, отсутствующий скрипт, директория вместо скрипта |
| `scripts/test_vfs_minimal.sh` | минимальная VFS: base64 с переносами и в одну строку, обычный ZIP, запуск без VFS |
| `scripts/test_vfs_multi.sh` | VFS из нескольких текстовых и двоичных файлов |
| `scripts/test_vfs_deep.sh` | VFS с вложенностью до пяти уровней и стартовый скрипт `vfs.vsh` этапа 3 |
| `scripts/test_vfs_errors.sh` | отсутствующий файл VFS, директория, пустой файл, не base64, base64 не архива, обрезанный ZIP |
| `scripts/test_commands.sh` | все режимы `ls`, `cd`, `uname` и `clear` (`commands.vsh`), VFS с домашней директорией пользователя хоста, управляющие последовательности `clear` через `cat -v` |
| `scripts/test_mv.sh` | все режимы `mv` (`mv.vsh`) на глубокой VFS, `mv` в двух других вариантах VFS, неизменность файлов VFS на диске после каждого запуска |

Стартовые скрипты для них лежат в `scripts/startup/`: `hello.vsh`, `demo.vsh`, `errors.vsh`,
`exit.vsh`, `tree.vsh`, `vfs.vsh` (этап 3), `commands.vsh` — сценарий этапа 4, проверяющий
все режимы новых команд, операции с VFS и обработку ошибок, `home.vsh` для VFS с домашней
директорией и `mv.vsh` — сценарий этапа 5 со всеми режимами `mv` и его ошибками.
