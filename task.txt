================================================================================
TASK SPECIFICATION: OS SHELL EMULATOR
================================================================================

Develop an emulator for an OS shell language. The emulator's behavior must be
as close as possible to working in the command line of a UNIX-like OS.

--------------------------------------------------------------------------------
Stage 1. REPL
--------------------------------------------------------------------------------
Goal:
Create a minimal prototype. Most functions in it are currently stubs, but 
interactive user dialogue is already supported.

Requirements:
1. The application must be implemented as a command-line interface (CLI).
2. The input prompt must be generated based on real OS data of the host machine 
   running the emulator. Example: username@hostname:~$.
3. Implement a parser that correctly handles quoted arguments.
4. Implement stub commands that output their name and arguments: ls, cd.
5. Implement the exit command.
6. Demonstrate the prototype in interactive mode. Provide examples of all 
   implemented functionality, including error handling.
7. Save the result of this stage to the repository with a standard formatted 
   commit.

--------------------------------------------------------------------------------
Stage 2. Configuration
--------------------------------------------------------------------------------
Goal:
Make the emulator configurable by supporting user parameter inputs to the 
application. Implement debug output of all specified parameters when launching 
the emulator for this stage.

Requirements:
1. Command-line parameters:
   - Path to the physical location of the VFS.
   - Path to the startup script.
2. Startup script for executing emulator commands: supports comments (use the 
   comment syntax of your implementation language). When executing the script, 
   both input and output must be displayed on the screen, simulating a user dialogue.
3. Report an error if an error occurs during the execution of the startup script.
4. Create several scripts for the host OS running the emulator. Include emulator 
   invocations in each script to test all supported command-line parameters.
5. Save the result of this stage to the repository with a standard formatted 
   commit.

--------------------------------------------------------------------------------
Stage 3. VFS (Virtual File System)
--------------------------------------------------------------------------------
Goal:
Connect a virtual file system (VFS).

Requirements:
1. All operations must be performed in memory. Unpacking or otherwise modifying 
   the VFS data on the physical disk is forbidden, except for possible utility 
   commands.
2. The source of the VFS is a ZIP archive. Binary data uses base64 or an equivalent 
   format.
3. Create several host OS scripts running the emulator. Include emulator invocations 
   in each script to test operation with different VFS variants (minimal, multiple 
   files, at least 3 nesting levels of files and folders).
4. Create a startup script to test all commands implemented in this and previous 
   stages. Include examples of all command modes, including VFS operations and 
   error handling.
5. Save the result of this stage to the repository with a standard formatted 
   commit.

--------------------------------------------------------------------------------
Stage 4. Basic Commands
--------------------------------------------------------------------------------
Goal:
Support commands simulating operations in a UNIX-like command line.

Requirements:
1. Implement the logic for ls and cd.
2. Implement new commands: uname, clear.
3. Create a startup script to test all commands implemented in this stage. 
   Include examples of all command modes, including VFS operations and error 
   handling.
4. Save the result of this stage to the repository with a standard formatted 
   commit.

--------------------------------------------------------------------------------
Stage 5. Additional Commands
--------------------------------------------------------------------------------
Goal:
Support more complex commands that modify the VFS state, where all modifications 
must take place strictly in memory.

Requirements:
1. Implement command: mv.
2. Create a startup script to test all commands implemented in this stage. 
   Include examples of all command modes, including VFS operations and error 
   handling.
3. Save the result of this stage to the repository with a standard formatted 
   commit.
